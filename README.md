# Night Sky map for digiKam / Marble

Build a "night sky" map theme for digiKam (and Marble) from NASA's Milky Way
panorama plus constellation and star data, then install it into digiKam's
Marble map directory.

The pipeline has three independent pieces:

| File | Purpose |
| --- | --- |
| `script.py` | Downloads the source data and produces `final/mirrored.jpg` plus the five `final/*.geojson.kml` layers. |
| `tile_maker.py` | Chops an equirectangular image into a `z/y/x` JPEG tile pyramid. |
| `night_sky.dgml` | Marble theme description that ties the panorama, tiles and KML layers together. |

`script.py` never installs anything. Copying files into digiKam is a manual
step (commands below).

## Requirements

* Python 3.9+ and the packages in `requirements.txt`:

  ```sh
  python3 -m pip install --user -r requirements.txt
  ```

* ImageMagick with the EXR and JPEG delegates, because the panorama step uses
  Wand. On Debian/Ubuntu:

  ```sh
  sudo apt install imagemagick libmagickwand-dev
  ```

* `curl` is used as a fallback when `urllib` downloads are rejected.

Free disk space: the downloaded `.exr` panorama is large (several GB) and the
generated tiles add ~22 MB for an 8k source.

## Running the pipeline

From the repository root:

```sh
python3 script.py
```

The script is best-effort: a failed step is reported but does not stop the
others, so the KML layers are still produced if, for example, the panorama
conversion fails. Progress lines are prefixed with `[OK]`, `[SKIP]`, `[WARN]`
or `[FAIL]`, and the final summary exits with status 1 if anything failed.

### Switches

All switches are constants near the top of the file, not command-line
arguments. Edit them and re-run the script.

| Switch | Default | Effect |
| --- | --- | --- |
| `download_huge_files` (`script.py`) | `True` | Set to `False` to skip all downloads and only process files already in `downloads/`. Useful on a slow link or when re-running after the data is present. |
| `mirror_x_geometry` (`script.py`, KML stage) | `True` | Mirrors longitudes when writing KML so the layers line up with the horizontally mirrored panorama. Leave it on for this theme. |
| `MAGICK_TMPDIR` (environment) | system temp | Point ImageMagick at a directory with enough free space for the EXR conversion. |
| `TILE_SOURCE` (environment) | auto-detected | Input image for `tile_maker.py`; use it to tile `final/mirrored.jpg`. |
| `MIN_ZOOM`, `MAX_ZOOM` (environment) | `0`, `7` | Zoom levels generated by `tile_maker.py`. |
| `TILE_SIZE` (environment) | `512` | Tile edge length in pixels. Marble reads the size from the level-0 tile, so other values also work as long as the whole pyramid is consistent. |

Example with the switches set for this repository:

```sh
MAGICK_TMPDIR=/tmp/python3 script.py
```

### Outputs

`script.py` writes:

```
final/mirrored.jpg
final/constellations_borders_mirror.geojson.kml
final/constellations_lines_mirror.geojson.kml
final/constellations_mirror.geojson.kml
final/dsos_mag6_mirror.geojson.kml
final/stars_6_mirror.geojson.kml
```

The source panorama is mirrored inside the KML stage, so `mirrored.jpg` and the
`.kml` layers are already consistent. Do not mirror the JPEG again.

## Generating tiles

`tile_maker.py` writes `tiles/<z>/<yyyyyy>/<yyyyyy>_<xxxxxx>.jpg`, which is the
layout Marble expects. `final/mirrored.jpg` is 8192x4096, so zoom 3 is 1:1 and
zoom 4 is a 2x upscale; generating 0-4 is enough:

```sh
MAX_ZOOM=4 TILE_SOURCE=final/mirrored.jpg python3 tile_maker.py
```

That produces 682 tiles (~22 MB) under `tiles/`. Higher levels are possible but
only add interpolated pixels for an 8k source; they make sense when starting
from the 32k starmap (1:1 is around zoom 5).

## Installing on Linux

digiKam's Marble data directory is separate from the theme files:

| Install | Theme directory |
| --- | --- |
| digiKam, native packages | `~/.local/share/digikam/marble_data/maps/earth/night_sky/` |
| digiKam, Flatpak | `~/.var/app/org.kde.digikam/data/digikam/marble_data/maps/earth/night_sky/` |
| Standalone Marble | `~/.local/share/marble/maps/earth/night_sky/` |

Create the directory and copy the theme, install map, layers and tiles into it
(tiles go directly in the theme folder, **not** into a `tiles/` subfolder):

```sh
THEME=~/.local/share/digikam/marble_data/maps/earth/night_sky
# Flatpak: THEME=~/.var/app/org.kde.digikam/data/digikam/marble_data/maps/earth/night_sky

mkdir -p "$THEME"
cp night_sky.dgml "$THEME"/
cp final/mirrored.jpg "$THEME"/
cp final/*.geojson.kml "$THEME"/
cp -r tiles/0 tiles/1 tiles/2 tiles/3 tiles/4 "$THEME"/
```

Then open digiKam and choose the theme in the map widget settings
(`Settings > Configure digiKam > GPS Map Widget`, or the map's own settings
menu). It appears as **Night Sky** under the Earth map themes.

### Windows

Use `%LOCALAPPDATA%\digikam\marble_data\maps\earth\night_sky\` and copy the same
files (`night_sky.dgml`, `mirrored.jpg`, the KML files, and the numbered tile
folders) into it. A system-wide install can instead use the `maps\earth\`
folder inside digiKam's own `data\digikam\marble\` directory.

## How the theme is put together

* `<target>` is `earth`. digiKam resolves theme IDs as
  `<target>/<theme>/<theme>.dgml`, so the folder name must match `<theme>`
  (`night_sky`).
* `<sourcedir>` is `earth/night_sky`, relative to Marble's `maps/` directory.
* The texture layer reads `<z>/<y6>/<y6>_<x6>.jpg` from the theme folder.
* `mirrored.jpg` is declared as `<installmap>`. If the tiles are missing,
  Marble can build a pyramid from it and place the result in its cache
  (`~/.cache/marble/maps/earth/night_sky/`). Marble refuses install maps larger
  than 21600x10800, so an 8192x4096 image is fine.
* The five KML files are referenced as `maps/earth/night_sky/*.geojson.kml`.

## Troubleshooting

**A download fails with HTTP 403.** `script.py` retries with `curl`, which some
hosts accept. If it still fails, fetch the URL manually and put it in
`downloads/` using the expected filename, then re-run with
`download_huge_files = False`.

**The panorama step fails.** Check that ImageMagick can read EXR and write JPEG
(`magick -list format | grep -i exr`), that `MAGICK_TMPDIR` points at a large
filesystem, and that Wand imports (`python3 -c "from wand.image import Image"`).

**The theme is listed but the background is black.** The tiles are probably in
the wrong place. They must be directly under the theme folder
(`.../night_sky/3/...`), not under `.../night_sky/tiles/3/...`. Verify with:

```sh
find "$THEME" -name '*.jpg' | head
```

**The layers do not line up.** Make sure `mirror_x_geometry = True` and that
you are using the `final/mirrored.jpg` / `final/*_mirror.geojson.kml` output,
not the unmirrored source files.

**The installed theme does not refresh.** Marble caches textures. Close
digiKam, delete `~/.cache/marble/maps/earth/night_sky/` if it exists, and
reopen. The cache is only used for tiles Marble generated itself.
